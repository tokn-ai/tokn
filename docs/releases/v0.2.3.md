# tokn v0.2.3

This release improves live model routing, adds OpenCode Go, fixes Codex account
refresh and usage reporting, and introduces isolated Docker tests for five agent
CLIs. It also moves repository metadata and release links to `tokn-ai/tokn`.
The SDK release preparation targets PyPI and npm at the same 0.2.3 version.

## Highlights

- Model discovery combines provider `/v1/models` responses with models.dev data.
  Explicit concrete model IDs remain routable while discovery refreshes
  periodically, without treating the bundled catalogue as the sole source.
- Per-model provider scores select the highest-scoring eligible account without
  requiring a complete provider list. Exact model rules and wildcard prefixes
  such as `gpt-*` load from ordinary configuration fragments.
- Codex OAuth credentials refresh through the provider flow and expose current
  usage information. Upstream failures retain useful non-JSON response details.
- OpenCode Go is available with API-key login, quota reporting, and model-specific
  Chat Completions, Responses, and Messages routing.
- The Docker agent-test harness runs OpenCode, Pi, DSH, Codex, and Claude Code in
  isolated containers. It verifies exact text responses, real fixture reads,
  endpoint-specific event streams, and persisted request history.
- Interrupted upstream streams retain their failure state and require the
  endpoint's terminal event. Abrupt peer disconnects are logged as benign closes.
- Python and TypeScript SDK packages embed the Rust routing engine, including
  generation builders, typed responses, streaming, and cancellation. Their
  separate registry workflows build and test installable packages before
  publication.
- The macOS desktop app manages a local gateway, account credentials and usage,
  routing configuration, and request inspection.

## Upgrade notes

- Model scores are sparse overrides. Providers without a matching score retain a
  neutral default, and a more-specific exact or prefix rule wins.
- OpenCode Go routes each model only through endpoints advertised for that model.
- The source repository is now `https://github.com/tokn-ai/tokn`.

## Downloads

The GitHub release workflow builds the CLI for Linux x86_64, macOS Apple Silicon
(aarch64), and Windows x86_64. PyPI `tokn-sdk` and npm `@tokn/sdk` use separate
manual release workflows. Their default runs build and test artifacts;
publication requires enabling the publish input and configuring the registry
publisher. See [SDK release preparation](../sdk-release.md).

The existing `v0.2.3` CLI tag identifies its original source. SDK preparation
retains the current source and uses a selected workflow ref at version 0.2.3.
